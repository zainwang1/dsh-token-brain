# Token 预算

省 token 的目标不是让回答变短，是让每一轮都只带必要信息。判断标准只有一条：删掉这段内容，任务结果会不会变差。会变差就留。

## 一、先知道钱花在哪

| 成本项 | 怎么产生 | 怎么降 |
|---|---|---|
| 系统提示与技能目录 | 每轮重发 | 改不动，别指望省这里 |
| 历史对话 | 每轮重发一遍，越滚越大 | 阶段后写状态卡，用状态卡替代旧历史 |
| 工具输出 | 读文件、跑命令、抓网页 | 先定位再读片段，限制行数，只留关键行 |
| 生成内容 | 输出的每个字都计费 | 交付优先、不重复、不铺垫 |
| 返工 | 理解错了重来 | 动手前对齐 brief，一次做对 |

长对话贵，主要贵在历史重放；大任务贵，主要贵在工具输出。先判断是哪一类，再谈省。

## 二、输入侧：能定位就不通读

1. 先列目录或搜索符号，再读文件；先拿行号，再读窗口。
2. 一个文件本轮读过就记住结论，不读第二次。
3. 日志、构建输出、网页：先找错误行，再读错误行周围几行，不整段贴回来。
4. 文档只取接口签名和最小示例，不整页加载。
5. 长对话进入新阶段前，写一张状态卡（目标、约束、已完成、待办、关键文件），后面靠它，不靠翻旧消息。

## 三、输出侧：先交付，再解释

- 结论、交付物、改动的文件放在最前面。
- 不重复用户的需求，不复述刚看过的内容，不写「好的，我来帮你」。
- 改动代码只给改动片段和位置，不整文件重贴。
- 同一段解释第二次出现时引用，不重写。
- 长文按节交付，先给结构确认一次，再展开。

## 四、什么绝对不能省

省 token 省出问题，通常是砍了这些：

- 约束与禁止项（「不要动数据库」「只用中文」）。
- 精确标识：文件名、函数名、版本号、路径、错误码。
- 数字与单位、时间、金额、比例。
- 安全边界与权限判断。
- 复杂推理的中间步骤：需要多步推导的任务，省掉步骤会直接算错。
- 验证结果：测试跑没跑、跑到哪一步、失败在哪里。

判断方法：如果把这段删了，读者或自己能不能复原？不能就留。

## 五、反模式

| 反模式 | 后果 |
|---|---|
| 为省而省，跳过读文件直接猜 | 改错文件、编 API、返工更贵 |
| 把工具输出截断到看不见关键行 | 判断错误，重新跑一遍 |
| 压缩历史时丢掉约束 | 越写越偏，最后重做 |
| 输出只给结论不给依据 | 用户不敢用，来回追问 |
| 用缩写和暗语代替术语 | 可读性下降，歧义成本更高 |
| 多轮小确认代替一次问清 | 每轮都重放历史，反而更贵 |

## 六、按任务规模的预算

- **小任务**（改一处、查一个事实）：一到两次工具调用，直接做，不写计划。
- **中任务**（改一个模块、写一篇稿）：先定位与对齐，再动手；阶段结束写三行状态卡。
- **大任务**（跨仓库、多文件重构、长期项目）：拆阶段，每阶段只加载本阶段需要的文件；用子 agent 做探索，只回收结论和关键路径。

不追求压到某个具体数字。目标是：一轮里没有未被使用的上下文。

## 七、自检

回答前问三句：

1. 我这轮读进来的内容，有多少没用到？
2. 我的输出里，有多少是重复或铺垫？
3. 我有没有为了短，漏掉约束、数字或验证结果？

前两问答「不少」就下次收紧；第三问答「有」就补回去。
